# 🏦 Bank Marketing - Прогнозування оформлення депозиту

## 📋 Опис проєкту

Цей проєкт присвячений побудові моделі машинного навчання для прогнозування ймовірності оформлення клієнтом строкового депозиту в банку на основі даних маркетингових кампаній португальської банківської установи.

**Задача**: Бінарна класифікація - передбачити, чи підпише клієнт строковий депозит (змінна `y`).

## 🎯 Основні цілі проєкту

1. Провести повний **Exploratory Data Analysis (EDA)**
2. Здійснити **препроцесинг даних** та **feature engineering**
3. Натренувати та порівняти **4+ моделей** машинного навчання
4. Провести **оптимізацію гіперпараметрів** (RandomizedSearch, Hyperopt)
5. Виконати **інтерпретацію моделі** за допомогою SHAP
6. Проаналізувати **помилки моделі** та запропонувати покращення

## 📊 Датасет

**Джерело**: [Kaggle - Bank Marketing Dataset](https://www.kaggle.com/datasets/sahistapatel96/bankadditionalfullcsv)

**Розмір**: 41,188 записів, 21 ознака

### Основні групи ознак:

#### 👤 Дані про клієнта:
- `age` - вік клієнта
- `job` - вид зайнятості
- `marital` - сімейний стан
- `education` - рівень освіти
- `default`, `housing`, `loan` - наявність кредитів

#### 📞 Дані про контакт:
- `contact` - тип зв'язку (cellular/telephone)
- `month`, `day_of_week` - час останнього контакту
- `duration` - тривалість дзвінка (⚠️ не використовується в фінальній моделі)
- `campaign` - кількість контактів в поточній кампанії
- `pdays`, `previous` - дані про попередні контакти
- `poutcome` - результат попередньої кампанії

#### 📈 Соціально-економічні показники:
- `emp.var.rate` - темп зміни зайнятості
- `cons.price.idx` - індекс споживчих цін
- `cons.conf.idx` - індекс довіри споживачів
- `euribor3m` - ставка Euribor
- `nr.employed` - кількість працевлаштованих осіб

#### 🎯 Цільова змінна:
- `y` - чи підписав клієнт депозит (yes/no)

## 🔍 Exploratory Data Analysis (EDA)

### Ключові спостереження:

1. **Дисбаланс класів**: ~88% клієнтів не оформляють депозит, ~12% оформляють
2. **Пропущених значень**: Немає
3. **Викиди**: Присутні в ознаках `age`, `campaign`, `pdays`, `previous`
4. **Кореляція**: Сильна кореляція між соціально-економічними показниками

### 📊 Візуалізації:
- Розподіл цільової змінної
- Розподіл категоріальних та числових ознак
- Кореляційна матриця
- Аналіз викидів (boxplots)

## 🛠️ Препроцесинг даних

### Feature Engineering:

Створено нові ознаки для покращення якості моделі:

1. `was_contacted_before` - чи був контакт раніше
2. `age_group` - вікові групи (young, middle, senior, retired)
3. `has_credit` - наявність будь-яких кредитів
4. `campaign_intensity` - інтенсивність кампанії
5. `prev_success` - успішність попередньої кампанії
6. `season` - сезон контакту

### Обробка даних:

- **Числові ознаки**: RobustScaler (стійкий до викидів)
- **Категоріальні ознаки**: OneHotEncoder (drop='first')
- **Розділення даних**: Train (70%) / Validation (15%) / Test (15%)
- **Цільова змінна**: Перетворена в бінарний формат (yes=1, no=0)

⚠️ **Важливо**: Ознака `duration` **НЕ використовується** в фінальній моделі, оскільки вона невідома до здійснення дзвінка.

## 🤖 Моделі машинного навчання

### Натреновані моделі:

1. **Logistic Regression** (baseline)
2. **k-Nearest Neighbors (kNN)**
3. **Decision Tree**
4. **XGBoost** (Gradient Boosting)

### 📈 Результати моделей:

| Модель | Val ROC-AUC | Коментар |
|--------|-------------|----------|
| Logistic Regression | ~0.75 | Baseline модель |
| kNN (k=5) | ~0.74 | Повільний inference |
| Decision Tree | ~0.73 | Сильний overfit |
| XGBoost (baseline) | ~0.78 | Хороші результати |
| **XGBoost (RandomizedSearch)** | **~0.79** | **+0.01 покращення** |
| **XGBoost (Hyperopt)** | **~0.80** | **+0.02 покращення** 🏆 |

**Висновок**: Оптимізація гіперпараметрів дала **+1-2% покращення ROC-AUC**, що є відмінним результатом для production-ready моделі.

## ⚙️ Оптимізація гіперпараметрів

### 1. RandomizedSearchCV (sklearn)

- **Метод**: Випадковий пошук в просторі гіперпараметрів
- **Кількість ітерацій**: 50
- **Cross-validation**: Stratified K-Fold (3 splits)
- **Scoring**: ROC-AUC

### 2. Hyperopt (Bayesian Optimization)

- **Метод**: Байєсівська оптимізація з TPE (Tree-structured Parzen Estimator)
- **Кількість оцінок**: 50
- **Простір пошуку**: Континуальний та дискретний
- **Переваги**: Використовує інформацію з попередніх спроб, ефективніше знаходить оптимум

### 🏆 Найкраща модель:

**XGBoost з оптимізованими гіперпараметрами (Hyperopt)**

- **ROC-AUC**: ~0.80 на validation, ~0.79-0.80 на test
- **Покращення**: +0.02 порівняно з baseline XGBoost
- **Стабільність**: Мінімальний gap між train/val/test (відсутність overfitting)
- **Час тренування**: ~5-10 хвилин для повної оптимізації

## 🔬 Інтерпретація моделі

### Feature Importance

TOP-5 найважливіших ознак (сумарна важливість):

1. **Соціально-економічні показники** (~30-35%): euribor3m, nr.employed, emp.var.rate
   - Найкритичніші для передбачення, відображають загальну економічну ситуацію
2. **Результат попередньої кампанії** (~15-20%): poutcome
   - Найсильніший індивідуальний предиктор (success/failure/nonexistent)
3. **Інтенсивність контактів** (~10-15%): campaign, previous
   - Критичний баланс: 1-3 дзвінки оптимально, >6 дзвінків негативно впливають
4. **Демографія клієнта** (~8-12%): age, education
   - Вік 40-60 років найактивніші, вища освіта позитивно корелює
5. **Сезонність** (~5-10%): month, day_of_week
   - Певні місяці (травень, серпень) показують вищу конверсію

### SHAP Analysis

**SHAP (SHapley Additive exPlanations)** використовується для детального пояснення впливу ознак:

- **Summary Plot**: Показує, як кожна ознака впливає на передбачення
- **Waterfall Plot**: Покрокове пояснення окремих передбачень
- **Bar Plot**: Середня важливість ознак

#### Ключові інсайти з SHAP:

**Фактори, що ЗНИЖУЮТЬ ймовірність** (негативний SHAP):
- 🔴 Високий euribor3m (>4.5%): -0.10 до -0.20 → економічна нестабільність
- 🔴 Багато дзвінків (campaign > 6): -0.10 до -0.15 → дратування клієнта
- 🔴 Минула невдача (poutcome=failure): -0.15 до -0.25 → втрата довіри
- 🔴 Молодий вік (<25): -0.05 до -0.10 → недостатньо заощаджень

**Фактори, що ПІДВИЩУЮТЬ ймовірність** (позитивний SHAP):
- 🟢 Минулий успіх (poutcome=success): +0.20 до +0.30 → найсильніший фактор!
- 🟢 Низький euribor3m (<2.5%): +0.10 до +0.20 → сприятлива економіка
- 🟢 Оптимальний вік (40-60): +0.08 до +0.15 → фінансова стабільність
- 🟢 Помірні контакти (1-3 дзвінки): +0.05 до +0.10 → увага без нав'язливості

## ❌ Аналіз помилок

### Confusion Matrix результати:

- **True Positives (TP)**: Правильно знайдені клієнти, що оформили депозит
- **True Negatives (TN)**: Правильно ідентифіковані клієнти, що не оформили
- **False Positives (FP)**: Помилково передбачили оформлення
- **False Negatives (FN)**: Пропущені клієнти, що мали оформити

### Типові помилки:

1. **False Positives**: Модель помиляється для клієнтів з середніми показниками
2. **False Negatives**: Пропускаються клієнти з нетиповою комбінацією ознак

## 📊 Метрики оцінки

### Чому ROC-AUC?

Через **значний дисбаланс класів** (~88% vs ~12%), використання лише accuracy було б некоректним.

### Основні метрики:

1. **ROC-AUC** - основна метрика (нечутлива до дисбалансу)
2. **F1-Score** - гармонійне середнє Precision та Recall
3. **Precision** - скільки з передбачених 'yes' дійсно 'yes'
4. **Recall** - скільки з реальних 'yes' ми знайшли
5. **PR-AUC** - краще для незбалансованих даних
